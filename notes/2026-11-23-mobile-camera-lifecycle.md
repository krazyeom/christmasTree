## 작업 개요

기존 ASCII 트리와 테마를 유지하면서 손인식 눈 효과의 모바일 조작과 종료 처리를 고쳤다. 이전 구현의 컴파일 결과만으로 판단하지 않고 실제 Chromium에서 렌더링과 입력을 확인했다.

## 아키텍처 결정

카메라 자원은 초기화 시도별로 관리한다. 전역 stop으로 이전 시도를 정리하면 새 시도까지 종료할 수 있어 사용하지 않는다. WebGL 버퍼는 렌더러 수명 동안 유지하고 변경 가능한 UI 상태만 ref로 읽는다. 모델·WASM은 기존 동일 출처 자산을 유지했으며 새 패키지는 추가하지 않았다.

## 보안 검증

카메라는 버튼으로만 시작하고 마이크를 요청하지 않는다. 영상 업로드·영구 저장 경로는 추가하지 않았다. 취소 후 늦게 받은 스트림도 정리하는 회귀 검사를 통과했다. 보안 출처가 아니면 권한 요청 전에 안내한다. 문서와 변경 코드에서 비밀정보·개인정보가 추가되지 않았는지 검토했다.

## 검증 및 배포 결과

- `npm run typecheck`, `npm test` (3개), `npm run build` 통과.
- 프로젝트 전용 PM2를 재시작했고 `http://localhost:37044`에서 실행 중이다. 이 주소는 해당 PC에서 확인한 주소이며 휴대전화용 공개 HTTPS 주소가 아니다.
- 실제 Chromium의 SwiftShader 소프트웨어 WebGL로 모바일 390×844, 데스크톱 1440×900을 검사했다. 두 화면 모두 가로 넘침과 JavaScript 오류가 없었다.
- 모바일: 28,000개 draw 호출을 확인했다. 픽셀 샘플 1,024개 중 998개가 비어 있지 않았다. CDP 터치 입력에서 한 손가락은 일반 reticle, 두 손가락은 pinching reticle, 모두 떼면 reticle 제거를 확인했다.
- 데스크톱: 100,000개 draw 호출과 비어 있지 않은 픽셀 샘플 959개를 확인했다.
- 두 화면에서 카메라 권한 거부 모의 입력의 안내, 강제 WebGL 컨텍스트 손실 후 ASCII 전환, 컨텍스트 복원 후 GPU 복귀를 확인했다.
- 실제 카메라의 손 영상 추론, 실물 휴대전화 Safari/Chrome, 하드웨어 GPU 성능 및 60fps는 검증하지 않았다. 원본 릴스와의 시각적 일치도 주장하지 않는다.
- 이 노트와 코드는 같은 커밋으로 main에 기록하고 origin에 푸시한다.
